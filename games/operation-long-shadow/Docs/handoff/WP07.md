## 2. Public APIs

**Services** (registered by `MissionSystems.Awake` through `MissionDirector.RegisterServices`):
- `IMissionDirector` → `MissionDirector`. Members: `Beat` (0 intro, 1–11, 12 outro), `IsRunning`, `StartMission()`, `ResumeFrom(cp)`, `QuitToSession()`, `Raise(id)`, `Flag`/`SetFlag`, `Stats`, `StoryClockMinutes`.
  - `ResumeFrom` reloads the in-memory snapshot when one exists. Otherwise it does a cold jump: earlier objectives, intel, gates, flags and sections are rebuilt from data, s is set to the checkpoint's value, the loadout is reset, and the player and squad are teleported to the checkpoint.
  - The class also exposes `CollectIntel(id)`, `TeleportToCheckpoint(cp)`, `BeginReload(death, cp)`, `MarkIntroSeen()`, `CurrentS`, `Finished`, `IsReloading`, `Runner`, `Log`, `Objectives`, `Checkpoints`, `Gates`, `Context`, `PlayerPositionOverride` and `PathProgressOverride`.
- `IObjectiveService` → `ObjectiveService`. Beyond the interface it has:
  - `Show(objectiveId, text)` (GDD §7.12 row plus its markers) and `SetText`.
  - `ShowTarget`/`HideTarget`/`ShowMarker` (markers follow a marker id, a squad member, an enemy or a destructible, using the Appendix A fallback until the target resolves).
  - `CollectIntel`, `HasIntel`, `CompletionOfBeat`, `DropBefore`.
  - Optional intel is not listed in `Active` and its icon is added only within 6 m.
- `ICheckpointService` → `CheckpointService`. Members: `Save` (deferred by GDD §17: enemy within 10 m, live grenade or HP < 50, at most 10 s, and committed at the next beat start), `Reload(deathInsert)` (hands over to the director's reload flow), `Register`/`Unregister`, `Last`, `SavePending`, `HasSnapshot`, `Restore`, `CommitPending`. Snapshots also capture every `InteractionPoint` in the scene.

## 3. Editor steps for the integrator (editor holder)

1. Land Mission (the LAND agent does this). Then run `AssetDatabase.Refresh()` and confirm the console shows 0 errors.
2. Run **LongShadow/Mission/Build All**. It builds `LIB_Mission` first and then `PF_MissionSystems`.
   - Missing intel models and photos are logged once and stay empty; the runtime then uses greybox pickups and cards without a photo.
   - Re-run it after `FAL_LEDGER_STACK`/`FAL_FILM_CAN`/`FAL_CODEBOOK` or the `IMG_INTEL_*` sprites land. The photos must be imported as Sprites; the builder warns otherwise.
3. WP11 places `Prefabs/Systems/PF_MissionSystems.prefab` in `S_Persistent`, adds `LIB_Mission` to the LibraryRegistry, and adds the link.xml entries. WP11 also registers the `IPlayerPosture` adapter and wires the smoke result. These are listed in REQUESTS.md "WP07 -> WP11".
4. Run **LongShadow/Mission/Validate Mission Data**. It checks line ids against DIALOGUE.json, scene ids and fallbacks against markup_ids.csv, and objectives against GDD §7.12, and writes `Logs/mission_validation.txt`. It must report OK.
5. Open the section scenes and run **LongShadow/Mission/Validate Scene Markup (Open Scenes)**. It lists every mission id still missing per beat and writes `Logs/mission_markup.txt`. Missing ids fall back to Appendix A, so this is a to-do list for WP10, not a blocker.
6. EditMode tests: run **LongShadow/Tests/Run EditMode Tests**, or `TestRunnerBridge.RunEditMode("LongShadow.Tests.EditMode.Mission")`. Expect 99 green, including the `LogAssert` test. Clear the console afterwards. The full-run tests share one autopiloted mission (about 1 s).
7. Play-mode checks:
   - Open **LongShadow/Mission/Beat Jump Window**. It jumps to any checkpoint, starts the mission, reloads, and shows the beat, s, the clock, the objectives and what each script waits for.
   - Then run **LongShadow/Mission/Run Smoke Test (Play Mode)**. It writes `Logs/smoke/smoke_<ts>.json` and screenshots to `Builds/captures/smoke_<ts>/`.
   - For a dev scene without Bootstrap, tick `MissionSystems._devAutoStart` and optionally set `_devStartCheckpoint`.
8. Offline (no editor): `Tools/mission/offline/run_offline_tests.sh [--filter=Name]`.

- **Section seams.** Mission requests the GDD §6.7 loads at beat starts and quiet points, and re-requests missed quiet loads at the next beat start. It never waits for a section mid-beat except at its own beat start (`WaitForSection`).
